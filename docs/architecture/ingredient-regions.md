# Matrix Flow Card：食材行决定加工区域

本轮定位：供有烹饪经验的用户快速阅读流程。食材单次列出，工序简短标注，区域跨度表示实际输入，详细指导保留在详情。

## 实现

- `ingredientDisplayOrder.ts` 从直接参与食材与已确认 material 上游建立加工集合。order 不传递食材。
- 保留已有合法行序；存在跳行时，通过有界连续集合搜索寻找显示排列。搜索失败或预算耗尽时保持原顺序，不改配方。
- `canRenderContinuousTable` 保留原始行序的严格诊断；`canRenderArrangedTable` 负责重排后的准入。工作台与 `resolveLayoutMode` 使用后者；布局及导出使用同一个显示排列。
- 连续表格用食材行边界延伸表达等待，不再重复绘制中央虚线与圆点。
- 分支布局中，只有输入集合与区域行范围完全一致时，工序高度覆盖这些行；非连续输入保留紧凑节点与必要导轨，不能夹带无关行。
- 表格宽度只测量主图实际可见的动作与参数；详情中的产物、状态与风味长句不再撑宽主图。终点完整说明仍在可访问详情中。
- 删除工具栏重复模式标签，读图指南改为流程速览。

## 验证

`npm run test:ingredient-regions`：覆盖展示重排、幂等、原始对象不变、合并后横线终止、等待通道、order 不传料、无解排列回退，及121道预置食谱的加工区域精确集合检查。

`npm run test:flow-linkage`：121道预置及1个旧版快照的现有接入与路径碰撞回归。旧断言固定了绕行坐标，本轮改为断言牛肉区域准确覆盖输入、芹菜与小料直接水平等待且不穿卡。

`test:continuous-table` 保留原行序跳行诊断；公开入口测试改用真实同列冲突验证回退，允许合法显示重排后进入表格。

本轮产物：`reports/ingredient-regions/audit.json` 与同目录样板SVG。统计为布局准入与结构检查，不表示配方事实已实测或全库视觉人工验收。

## 边界

不改食谱内容、不发布草稿、不写入云端。旧已发布食谱仍可能缺少完整依赖，布局不能补造回锅事实。原始无依赖食谱按已有参与集合呈现，不将其假称已确认物料流。

有界搜索不是完备的任意规模排布求解器。未找到合法排列时保留分支表达。未新增分次用量推断。

## 本轮执行结果

- 121 道预置：114 道允许连续表格，7 道保留分支；32 道采用合法的显示重排。
- type-check、build、test:ingredient-regions、test:flow-linkage、test:continuous-table、test:flow、test:domain、test:round-trip 均通过。
- audit:presets 为121道通过，仍有85条警告；通过不代表原著事实或厨房实测认证。
- 浏览器查看本地 cn-59 的连续表和分支图，并在390px视口检查全图横向滚动；检查详情点击、Space打开、Escape关闭与焦点恢复。此为样板人工检查，非全库逐张人工验收。
- 终点说明移入可点击/键盘访问的详情，主图保留简短标题与必要参数。
