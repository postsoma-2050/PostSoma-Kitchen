# PostSoma Kitchen · 连续工序表 (Continuous Process Table) 设计与布局规范

## 一、核心设计目标与阅读逻辑

连续工序表的核心目的在于：**让烹饪者从任意一行食材向右平视阅读，即可一目了然地获知其何时加入、与何物汇合、经历何种工序，并最终如何完成**。

打破“在格子里写长篇作文”与“密集悬浮卡片连线图”的传统形态，建立由**表格单元格合并、边界自然约束、横向时序延展**构成的现代化可视化烹饪矩阵表。

---

## 二、核心视觉与布局规则

### 1. 原料行 (Ingredient Rows)
- **一次性纯粹表达**：每种原料名称与用量仅在最左侧食材单元格展示一次，严禁名称冒充用量或在后续阶段重复列出已有食材。
- **预备处理区分**：原料的预备处理（如“切块”、“对半切”、“泡发”）应与原料主名称在视觉和结构上清晰区分。
- **时序延展通道**：尚未在当前阶段加入的原料，其横向行通道继续向右延伸（作为空白等待行），直到其首次被加工或汇入的列为止。严禁让用户误以为未参与的原料已在早期阶段被处理。

### 2. 合并区域 (Merged Process Regions)
- **真实物料合并**：**只有在该阶段确实属于同一个处理对象（混合物/同锅物料）的相邻连续食材行，才允许合并**。
- **内部线条终止**：两行或多行食材一旦合并为一个处理对象，其内部的横向水平分割线立即**终止**，外围连续边框向右延续，表示已融为一体。
- **动作语义精炼**：合并区域内的烹饪动词保持精炼（如“融化”、“混合”、“翻拌”、“收汁”），主动作大字突出，英文副标弱化为次级层级；不机械强制四字限制，以保留准确烹饪语义为先。

### 3. 工序输入 (Step Inputs & Upstream Streams)
- **增量输入原则**：每一个工序接收的是“**本次新加入原料 ＋ 上游延续下来的半成品流**”。
- **禁止重复记账**：不能把历史已加入并加工的原料当作新原料再次引入。
- **严禁几何臆测**：物料流向严格基于领域依赖事实（`dependencies`），绝不根据矩形在画布上的几何相交或器具同名虚构物料汇流。

### 4. 暂存与等待 (Staging / Hold Aside vs Waiting)
- **暂存支线真实性**：
  - 例如滑牛肉盛出备用（`cn-59`）：牛肉经上浆滑炒后盛出暂存，此时牛肉不参与下一工序（炒芹菜），其物料流向直接通向下一步的回锅合炒。
  - 同锅等待（`order` 依赖，如留底油串行约束）与实际物料汇合（`material` 依赖）是不同的领域事实。
- **极简支线表达**：
  - 暂存支线使用清爽的细虚线/实线、精准单向箭头及清晰的物料标签（如“暂存牛肉回锅”）。
  - 常规的线性连续合并绝不叠加“圆点 ＋ 导轨 ＋ 连线箭头”三套冗余符号，区域边界与网格自然即是连接。

### 5. 复杂图结构与安全降级机制 (Complex Topologies & Safety Fallback)
- **连续工序表准入硬性契约**：
  1. **严格连续性 (Strict Contiguity)**：工序所涉及的食材行集合（直接原料 + 上游物料）跨度必须严格等于实际参与行数（`span === rows.length`）。严禁跳过任何单行或多行中间无关食材进行大矩形包裹！
  2. **严格物料边 (Explicit Material Edges Only)**：仅显式声明为 `type === 'material'` 的上游依赖才允许将物料汇入下游区域。严禁把未确认语义的 `legacy` 依赖当作已确认物料流直接吸收上游行，遇未确认依赖必须拒绝连续表格准入并提示确认。
  3. **同阶段区域无冲突 (Zero Intra-Stage Collision)**：同一阶段（列）内并行的各个工序，其食材行范围必须绝对互斥（零重叠）。若存在多工序同时占有相同食材行导致实体重叠，系统必须立即安全降级为分支流程图，严禁后画覆盖前画。
  4. **暂存通道通行性 (Hold-Aside Clear Corridor)**：暂存备用跨列走廊在中间跨越阶段必须拥有至少一行空闲通道，不得与中间工序实体卡片相撞穿透。
- **模式自适应与降级保护**：
  - 若食谱满足上述全部 4 项准入契约，默认呈现优雅的“连续工序表 📋”；
  - 若任一契约不满足，系统在控制台与工具栏明确提示具体的结构原因（如“工序跳过第 2 行食材”、“第 1 阶段存在行冲突”），并安全自动降级为“分支流程图 🔀”，同时禁用强制表格渲染，绝不失真表达物料事实。
- **用户自决权**：在满足准入条件的食谱上，工作区提供“连续工序表 📋”与“分支流程图 🔀”的双向自由切换。

## 三、信息层级与样式准则

1. **去冗余外框**：移除多层阴影与沉重外层包裹，强化 SVG 表格本身的轻盈与质感。
2. **比例平衡**：食材列初始设计参考宽度约占总宽的三分之一左右，根据实际食材名称长度动态自适应。
3. **顶栏预置信息**：容器大小（器具）与预热等前置处理收敛于紧凑顶栏，标签左对齐，层级适度。
4. **终点主操作**：成品栏主标题必须为操作动词（如“出锅装盘”、“烘焙完成”），风味与口感描述作为次级指导信息展示。
5. **双语呈现策略**：有副标题时以弱化层级呈现，无副标题时不补造虚假英文。
